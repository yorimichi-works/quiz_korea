# Quiz Battle 共通基盤 README

> 韓国語圏を第一市場とする、1対1・リアルタイム早押しクイズ。
> 本書は、クライアント・バックエンド・問題DB・運営画面が共通して参照するMVPの基準仕様である。

## 1. プロダクト概要

プレイヤー同士をオンラインでマッチングし、問題文が順次表示される早押しクイズで対戦する。分かった時点でボタンを押し、先に押したプレイヤーだけが回答する。正解を5問先取したプレイヤーが勝者となる。

賞金や定時開催を前提とせず、短時間の対戦、レーティング、降格しないランク、即時再戦を継続動機の中心に置く。

### MVPの一文説明

問題を先に見抜いて押し、5問先取を目指す1vs1リアルタイムクイズ。

### 初期対象

- 第一言語・市場：韓国語／韓国
- 形式：スマートフォン中心。Webでも同一ルールを提供
- 対戦：ランダムマッチング
- 1試合：目安2〜5分
- ログイン：匿名ですぐ開始可能。アカウント連携でデータを保持

## 2. コアゲームルール

### 2.1 勝敗

- 1対1で対戦する。
- 1問正解するごとに1ポイントを得る。
- 先に5ポイント獲得したプレイヤーが勝利する。
- 両者が5点へ到達することはないため、引き分けは設けない。
- 1試合は最大20ラウンドとする。
- 20ラウンド終了までに5ポイントへ到達しなかった場合は、その時点の得点が高いプレイヤーを勝者とし、同点なら無効試合とする。

### 2.2 ライフ

- 各プレイヤーは試合開始時に3ライフを持つ。
- 誤答または回答時間切れで1ライフ減る。
- ライフは正解しても回復しない。
- 0ライフになったプレイヤーはその時点で敗北する。
- 勝利条件は「5問先取」または「相手のライフを0にする」のいずれか早い方。
- 初期ライフ数はRemote Config等で変更可能な定数とし、コードへ直書きしない。

### 2.3 出題と早押し

1. サーバーが問題を確定し、両クライアントへ同一の開始時刻を通知する。
2. 3、2、1の短いカウントダウン後、問題文を一定速度で順次表示する。
3. プレイヤーは回答が分かった時点で早押しボタンを押す。
4. サーバーが最初に受理した有効な押下を勝者とし、そのプレイヤーへ回答権を与える。
5. 回答権を得たプレイヤーは制限時間内に文字入力して送信する。
6. 正解なら1ポイントを獲得し、その問題を終了する。
7. 不正解または時間切れなら1ライフを失い、その問題の回答権を失う。
8. 相手がまだその問題で誤答していなければ、残りの問題文を表示後、相手のみ再度押せる。
9. 両者が誤答するか、誰も押さず問題時間が切れた場合は無得点で次問へ進む。

### 2.4 1問内の回答権

- 1人につき1問1回まで。
- 誤答したプレイヤーは同じ問題で再回答できない。
- 一方が誤答した後、相手には即時に正解を見せない。
- 相手の単独回答可能時間は、問題文の表示終了後を含め最大10秒とする。
- 正答発表は、その問題が完全に終了してから両者へ同時表示する。
- 両者とも回答せず時間切れになった場合は、正答を画面中央に約5秒表示してから次問へ進む。

### 2.5 1問の時間設定（MVP推奨値）

|項目|初期値|備考|
|---|---:|---|
|試合開始カウントダウン|3秒|演出込み|
|問題文の表示|1文字あたり80ms|韓国語基準。句読点で短く停止可|
|問題文表示後の猶予|5秒|誰も押さない場合|
|回答入力|7秒|押下確定時から計測|
|誤答後の相手側猶予|最大10秒|問題全体の進行に合わせる|
|正誤結果表示|2秒|次問へ自動遷移|
|両者時間切れ時の正答表示|5秒|正答を中央表示して次問へ自動遷移|
|切断復帰猶予|45秒|超過で原則敗北|

すべてサーバー設定値として変更可能にする。

### 対戦モードとの関係

- ランクマッチ／빠른 대전：全ジャンルから出題する。
- カテゴリ対戦：選択ジャンルのみから出題する。MVP後に開放する。
- ランクマッチでは、直近の問題との重複、同一ジャンルの過度な連続、難易度の偏りを避ける。
- 初期MVPではジャンルごとの細分化より、問題数と検証品質を優先する。

## 4. レーティングとランク

### 4.1 二つを分離する

- レーティング（MMR）：実力推定値。勝敗によって上下する。
- ランク：到達実績。昇格するが、一度到達したランクからは下がらない。
- 表示用レートとマッチング用MMRは将来分離可能なデータ構造にする。MVPでは同値でよい。

### 4.2 MVPレーティング

- 初期値：1,000
- Elo方式を基礎とする。
- 初期K値：32
- 最初の10戦は認定期間としてK値48を適用する。
- 切断敗北も通常の敗北として計算する。
- 無効試合、サーバー障害、対戦成立前の離脱では変動させない。
- 同一相手との短時間の反復対戦は不正対策として変動量を縮小できるようにする。

### 4.3 ランク案

|ランク|到達レート|降格|
|---|---:|---|
|브론즈 / Bronze|初期|なし|
|실버 / Silver|1,100|なし|
|골드 / Gold|1,250|なし|
|플래티넘 / Platinum|1,400|なし|
|다이아 / Diamond|1,600|なし|
|마스터 / Master|1,850|なし|
|그랜드마스터 / Grandmaster|2,100|なし|

- 到達した最高ランクをhighestRankとして保存する。
- 現在レートが閾値を下回っても、バッジとランク表示は維持する。
- ランキング順位はランクではなく現在レートで決める。
- 閾値は運営データを見て変更可能にする。

## 5. マッチング

### MVPフロー

1. プレイヤーが「빠른 대전」を押す。
2. 待機キューへ入り、近いMMRの相手を検索する。
3. 待機時間に応じて許容レート差を段階的に広げる。
4. 対戦をサーバー側で確定し、両者へ同じmatchIdを通知する。
5. 両者の接続確認後、問題セットを確定して試合を開始する。

### 推奨探索幅

- 0〜5秒：±100
- 5〜10秒：±200
- 10〜20秒：±350
- 20秒以降：制限を段階的に解除

匿名プレイヤーもマッチング可能。ただしランキング掲載、長期成績保持、ユーザー名設定等はアカウント連携を促す。

## 6. 問題と正誤判定

### 問題データの最低項目

```text
questionId
locale
categoryId
difficulty
questionText
canonicalAnswers[]
acceptedAliases[]
rejectedNearMatches[]
explanation
sourceUrls[]
reviewStatus
version
createdAt / updatedAt
```

### 判定方針

- クライアントではなく、サーバーが正誤を確定する。
- Unicode正規化、前後空白除去、大小文字・一般的な分かち書き差を吸収する。
- 人名・作品名・外来語は、事前登録した別表記のみ許容する。
- 意味判定をLLMへ全面依存しない。対戦中の判定は決定的かつ再現可能にする。
- 表記揺れ追加のため、誤判定報告を保存する。
- 問題文、正答、解説、出典を独自に作成・検証し、他社問題DBを転載しない。

## 7. 試合状態モデル

```text
MATCHING -> READY -> COUNTDOWN -> READING_QUESTION -> BUZZ_LOCKED
  -> ANSWERING -> JUDGING -> REBOUND -> QUESTION_RESULT
  -> READING_QUESTION -> MATCH_RESULT -> REMATCH_WAIT -> CLOSED
```

- 状態遷移の正本はサーバーとする。
- クライアントはサーバー時刻との差分を保持し、表示を補間する。
- 押下順はクライアントの自己申告時刻ではなく、サーバーで受理したイベントと補正可能な接続情報から決める。
- 同時押しの差が判定限界以下の場合に備え、同着処理を用意する。MVPではサーバー受理順を採用し、監査ログを残す。

## 8. 画面構成とUI原則

### デザイン方向

- 白を主背景にする。
- コバルトブルー／ネイビーを基本色、黄色またはライムを早押し・成功のアクセントに使う。
- 通常時は静かに、押下・正解・勝利の瞬間だけ強く反応させる。
- 既存アプリのロゴ、配色、キャラクター、効果音、画面表現を模倣しない。
- 添付参考画面からは、上部の対戦状況、中央の問題、下部の操作という情報階層のみ参考にする。

### 必須画面

1. ホーム：빠른 대전、レート、ランク、オンライン人数
2. マッチング：探索状況、キャンセル
3. 対戦準備：相手名、レート、ランク
4. 対戦：両者の得点・ライフ、問題番号、問題文、早押しボタン
5. 回答入力：入力欄、残り秒数、送信
6. 問題結果：正答、短い解説、得失点
7. 試合結果：勝敗、レート変動、ランク到達、再戦
8. プロフィール：戦績、最高ランク、ジャンル別成績
9. ランキング
10. 通報・問い合わせ

## 9. 通信・サーバー権威

リアルタイム対戦では、マッチング確定、問題選択と順序、問題開始時刻、早押し受理順、回答期限、正誤判定、得点・ライフ、勝敗、レート変動を必ずサーバー権威で処理する。

クライアントから送るのは意図（buzz、answer、ready等）であり、得点や残りライフを直接更新させない。

## 10. 切断・離脱・例外

- 対戦開始前に接続できなければマッチを破棄し、レートは変動させない。
- 試合中の切断は45秒まで復帰を待つ。
- 復帰中も試合状態はサーバーで保持し、相手には待機表示を出す。
- 猶予超過は切断した側の敗北とする。
- 両者切断、サーバー障害、問題データ不整合は無効試合とし、レートを戻せる監査記録を残す。
- アプリのバックグラウンド移行も切断と同等に扱うが、即敗北にはしない。

## 11. 不正・荒らし対策

- 早押し・回答イベントにレート制限と重複排除キーを付ける。
- 正答をクライアントへ事前送信しない。
- 問題セットを一括で露出させず、必要な時点で配信する。
- 異常に短い反応時間、連勝パターン、同一端末・同一相手の反復を記録する。
- 切断を使ったレート回避を防ぐ。
- 表示名・プロフィールにはNGワード、個人情報、URL等の検出を適用する。
- 問題・ユーザー・対戦結果に通報導線を設ける。

## 14. 受け入れ条件

- 2台の端末で同じ問題が同期して表示される。
- 同時押下でも回答権が一人だけに確定する。
- 誤答者のライフが1減り、同じ問題で再回答できない。
- 誤答後、相手には一度だけ回答機会がある。
- 正解5問または相手ライフ0で試合が確実に終了する。
- 切断後45秒以内なら同じ試合状態へ復帰できる。切断中も試合時間は進み、回答中に切断したプレイヤーはその問題の回答権を失う。
- 試合結果とレート更新が二重計上されない。
- レートは下がっても、一度到達したランクは下がらない。
- 正答データを通常のクライアント通信から取得できない。
- 問題ごとの判定結果を監査可能である。

## 15. 実装前に最終決定する可変項目

以下は本READMEの推奨値で進められるが、プレイテスト後に調整する。

- 初期ライフ：推奨3
- 回答時間：推奨7秒
- 問題表示速度：推奨80ms／文字
- 誤答後の相手側猶予：推奨最大10秒
- EloのK値とランク閾値
- ランクマッチの問題難易度配分
- 表記揺れの許容範囲
